# ویرایشگر گردش (نمودار + فهرست)

هدف: فرآیند با **گروه / حلقه / شرط**؛ مراحل همیشه داخل گروه (به‌جز اقدام‌های آزاد روی بوم در نسخه فعلی).

## بوم اصلی

- شکل‌ها: شروع، **گروه**، **شرط**، **اقدام**
- **دبل‌کلیک** روی گروه → طراح داخل گروه
- راست‌کلیک → مشخصات / تبدیل گروه↔اقدام (بر اساس قوانین فعلی)
- یال‌ها: بعدی، موفقیت، شکست
- عرض نود اقدام با عنوان کامل فیت می‌شود

## نمای درون‌گروه

- شروع تو‌در‌تو، اقدامات، شرط‌ها
- «بازگشت به نمودار»

## سلکتور (inspector)

هر فیلد سلکتور:

| کنترل | معنی |
|--------|------|
| سوئیچ سلکتور پویا | منبع/ستون + توکن `{مقدار پویا}` داخل CSS |
| تکس‌باکس سلکتور | مقدار CSS |
| ذخیره / خواندن از حافظه | JSON `DASEL:` (افزونه + localStorage) |
| زنجیره فریم (JSON) | زیر سلکتور — مسیر فریم تا المان |
| سوئیچ دارای اتریبیوت | `[name="value"]`؛ مقدار ثابت یا پویا از دیتاسورس |

## ویژگی‌های شروع / تکرار

- روی نود **شروع** (ریشه یا داخل گروه): None / Loops / Elements / DataSource
- منابع اکسل و دیتاسورس مادر روی شروع فرآیند

ذخیره: گراف در `GraphJson` (`Processes`) / کش localStorage؛ `PUT /api/tasks/{id}/canvas` روی سرور.

## انواع اقدام (ActionType)

همهٔ انواع زیر در **موتور اجرا** و **ویرایشگر** پیاده شده‌اند. ستون «سلکتور» یعنی نود به یک
المان صفحه نیاز دارد؛ «مقدار» یعنی فیلد مقدار (ثابت / منبع داده / حافظه / سیستم) نمایش داده می‌شود.

| اقدام | کاربرد | سلکتور | مقدار | پارامتر ویژه |
|-------|--------|:------:|:-----:|--------------|
| `NoAction` | بدون اقدام (نقطهٔ عبور) | — | — | — |
| `Click` | کلیک روی المان | ✅ | — | — |
| `DoubleClick` | دبل‌کلیک | ✅ | — | — |
| `RightClick` | کلیک راست (contextmenu) | ✅ | — | — |
| `Hover` | نگه‌داشتن نشانگر روی المان | ✅ | — | — |
| `Enter` | کلید Enter روی المان | ✅ | — | — |
| `InputContent` | نوشتن متن در فیلد | ✅ | ✅ | — |
| `InsertContent` | درج محتوا | ✅ | ✅ | — |
| `LoadContent` | بارگذاری محتوا | ✅ | ✅ | — |
| `TakeContent` | خواندن محتوا از صفحه | ✅ | ✅ (منبع) | مقصد ذخیره: حافظه / منبع داده |

| `NewPage` | باز کردن تب جدید با آدرس | — | ✅ | همان |

| `WaitTime` | انتظار زمانی (ms) | — | ✅ | — |
| `WaitForLoading` | انتظار بارگذاری | ✅ | — | — |

(مرورگر این کلید را از JavaScript قابل مشاهده نمی‌کند، پس موتور فرم را صریحاً submit می‌کند).

## انواع شرط (ConditionType)

| شرط | بررسی | سلکتور | مقدار مقایسه |
|-----|-------|:------:|:------------:|
| `None` | انتخاب نشده | — | — |
| `Url` | آدرس تب جاری | — | ✅ (الگو) |
| `ElementValue` | متن/مقدار یک المان | ✅ | ✅ |
| `SourceValue` | مقدار یک ستون از منبع داده | — (منبع/ستون جدا) | ✅ |
| `FindElement` | وجود المان | ✅ | — |
| `NotFindElement` | نبود المان | ✅ | — |
| `ElementVisible` | وجود **و مرئی‌بودن** المان | ✅ | — |
| `ElementHidden` | نبود یا **پنهان‌بودن** المان | ✅ | — |
| `FindElements` | تعداد المان‌های صفحه | ✅ | ✅ (عدد) |
| `DriverTabs` | تعداد تب‌های مرورگر | — | ✅ (عدد) |
| `SystemDate` | تاریخ سیستم (ساعت ماشین) | — | ✅ + قالب |
| `SystemTime` | زمان سیستم (ساعت ماشین) | — | ✅ + قالب |

### قالب تاریخ/زمان سیستم

مقدار از **ساعت همان دستگاه** خوانده می‌شود (جدا از ساعت سایت). مقدار مقایسه باید **دقیقاً**
با همان قالب هم‌شکل باشد، وگرنه شرط هرگز برقرار نمی‌شود.

| `SystemDate` | نمونه | | `SystemTime` | نمونه |
|--------------|-------|-|--------------|-------|
| `yyyy-MM-dd` | 2026-09-25 | | `HH:mm:ss` | 14:05:09 |
| `yyyy/MM/dd` | 2026/09/25 | | `HH:mm` | 14:05 |
| `dd-MM-yyyy` | 25-09-2026 | | `HHmmss` | 140509 |
| `yyyyMMdd` | 20260925 | | | |
| `Timestamp` | میلی‌ثانیه از ۱۹۷۰ | | `Timestamp` | میلی‌ثانیه از ۱۹۷۰ |

**تفاوت `ElementVisible` با `FindElement`:** `FindElement` فقط وجود المان در DOM را بررسی می‌کند؛
`ElementVisible` علاوه بر آن، مرئی‌بودن (نه `display:none`، نه `visibility:hidden`، نه `opacity:0`،
و دارای ابعاد) را هم می‌خواهد. برای صفحه‌هایی که نسخهٔ پنهان یک نود را نگه می‌دارند مفید است.

## حلقه: «تا وقتی شرط برقرار نشه گیر کن»

برای انتظار روی یک شرط، یک **یال بازگشتی** بکشید: از شاخهٔ `fail` شرط به مرحله‌ای که وضعیت
را تغییر می‌دهد، و از آن مرحله **به همان شرط** برگردید.

```
شرط ──fail──> مرحله ──next──> همان شرط     (تکرار)
شرط ──success──> ادامهٔ کار                (خروج)
```

| نکته | توضیح |
|------|--------|
| ارزیابی مجدد | در هر بازگشت، شرط **دوباره** ارزیابی می‌شود |
| سقف تکرار | فیلد **«حداکثر بازگشت حلقه»** روی نود `شروع` (پیش‌فرض ۱۰۰) |
| رسیدن به سقف | اجرا با پیام روشن و نام نود متوقف می‌شود (نه بی‌صدا) |
| مکث هر دور | حداقل ۵۰۰ms خودکار، حتی اگر «فاصله بین مراحل» صفر باشد |
| توقف دستی | دکمهٔ توقف/پاز در هر دور کار می‌کند |
| join الماسی | اگر دو شاخه به یک نود برسند، آن نود **دو بار** اجرا می‌شود |

> برای انتظار ساده (بدون تغییر وضعیت صفحه) لازم نیست حلقه بکشید — از شرط با گزینهٔ
> «انتظار تا ظاهر شدن المان» یا اقدام `WaitForElement` استفاده کنید.

## فیلدهای «حداکثر انتظار (ms)»

دو مفهوم جدا وجود دارد و در رابط کاربری هم جدا نمایش داده می‌شوند:

| کجا | معنی |
|-----|------|
| ویژگی‌های فرآیند → **فاصله بین مراحل (ms)** | مکث بعد از **هر** مرحله پیش از رفتن به مرحلهٔ بعد |
| اقدام `GoToUrl` / `Navigate` / `NewPage` → **حداکثر انتظار (ms)** | سقف انتظار برای **تکمیل بارگذاری صفحهٔ مقصد** |
| اقدام `WaitForElement` → **حداکثر انتظار (ms)** | سقف انتظار برای **ظاهر شدن المان** |

> فیلدهای قدیمی `delayBeforeMs` / `delayAfterMs` (که در واقع توسط موتور خوانده نمی‌شدند) از رابط
> کاربری حذف شده‌اند؛ تنها کنترل واقعی مکث، «فاصله بین مراحل» روی نود شروع است.
