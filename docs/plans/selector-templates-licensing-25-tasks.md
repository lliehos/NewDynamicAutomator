## قواعد اجرا (الزامی — بدون استثنا)

این قواعد را کارفرما تعیین کرده و در تمام مراحل باید رعایت شود:

1. **هر کار جداگانه** انجام شود و **قبل از رفتن به کار بعدی** کامل شود.
2. برای **هر کار** بیلد گرفته شود.
3. برای **هر کار** تست کاربری (اجرای واقعی روی اپ / هارنس) انجام شود.
4. اگر مشکل نبود → **کامیت مستقل** و سپس **پوش مستقل** برای همان کار.
5. **هیچ سؤالی پرسیده نشود — مخصوصاً بعد از شروع اجرا.** اگر ابهام بود، محتمل‌ترین تفسیر
   انتخاب و اجرا شود. سؤال‌ها (اگر واقعاً لازم بودند) فقط **قبل از شروع** یک‌جا پرسیده شوند و
   بعد از آن دیگر هیچ سؤالی پرسیده نشود.
6. **هیچ گزارشی داده نشود.** خروجی هر کار فقط یک خط: `#<شماره> <done|blocked> <hash>`
7. در صورت بروز مشکل و بلاک شدن، همان یک خط با `blocked` ثبت شود و به کار بعدی برود.

> این بند ۵ و ۶ صریحاً به درخواست کارفرما اینجا درج شده است: **سؤال نپرس، گزارش نده.**

### قواعد کیفیت (تأکید کارفرما)

- **دوزبانه بودن (i18n):** هر لیبل/متن جدید باید **هم در `fa.json` و هم در `en.json`** اضافه شود.
  هیچ متن hard-code فارسی یا انگلیسی در ویو/JS نماند (به‌جز موارد فنی).
- **انکدینگ فارسی:** همه فایل‌ها **UTF-8 (без BOM)** باشند. نوشتن فایل با PowerShell فقط
  با `-Encoding utf8` مجاز است. کاراکترهای `ی`/`ک` فارسی و نیم‌فاصله (ZWNJ = `\u200c`) حفظ شوند.
  پس از هر ویرایش، JSONها اعتبارسنجی شوند و متن فارسی **در مرورگر** بازبینی شود، نه فقط در
  ترمینال (ترمینال متن فارسی را خراب نشان می‌دهد).
- **عنوان ستون‌های منبع ممکن است فارسی باشد** — هر کدی که با نام ستون کار می‌کند باید یونیکد-امن باشد.
- **عدم اضافه‌کاری:** منطق تجاری قدیمی باید وفادارانه پورت شود؛ هیچ جریان/فیلد/صفحهٔ ناخواسته
  اضافه نشود. در عوض، منطق جاافتادهٔ قدیمی جبران شود.

## یادداشت‌های فنی (پیش از هر کار بررسی شود)

### قواعد عمومی این پروژه (از حافظهٔ قبلی)

- **UI دوزبانه:** کلیدها در `src/Morobot.Web/wwwroot/locales/{fa,en}.json`. کلید تکراری در
  یک سطح، کلید قبلی را سایه می‌اندازد.
- **دیتابیس:** `Server=.;Database=MorobotV3;Trusted_Connection=True;TrustServerCertificate=True`.
  کوئری: `sqlcmd -S . -d MorobotV3 -E -C -Q "..." -W -s "|"`.
- **پورت dev:** `http://localhost:7200`. ورود: `pro`/`Pro123!` (پنل)، `admin`/`Admin123!` (ادمین).
  ورود یک‌کلیکی dev: `/Panel/Account/DevLogin?userName=pro|admin|free|guest`
  (فقط کاربران seed‌شده؛ **باید اول خروج کرد** چون کوکی ادمین قدیمی ریدایرکت می‌کند).
- **ساخت (build):** قبل از build باید `Stop-Process -Name "Morobot.Web"` اجرا شود (قفل DLL).
  اجرا:
  `Set-Location "src\Morobot.Web"; $env:ASPNETCORE_ENVIRONMENT="Development"; Start-Process -FilePath "dotnet" -ArgumentList 'run','--no-build','--urls','http://localhost:7200' -WindowStyle Hidden`
- **برای تغییر JS/CSS حتماً `?v=` عوض شود** و build مجدد گرفته شود.
- **الگوی کامیت:** پیام در `_run/msg-N.txt`، سپس
  `git add -A; git commit -q -F "_run\msg-N.txt"; git push -q`.
- **ثبت در پلن:** `node _run/record-task.js <num> <hash>`.

### هشدار نوشتن با sqlcmd (تکرار نشود)

- `sqlcmd -Q` با مقدار طولانی (> چند KB) **بریده** می‌شود → گراف ناقص ذخیره می‌شود.
- `sqlcmd -i` فایل اسکریپت را ANSI می‌خواند و متن فارسی را `?` می‌کند (حتی با BOM).
- `-y 0` و `-h -1` **با هم قابل استفاده نیستند** (خطای mutually exclusive).
- `CHARINDEX('"x":1', @g)` از طریق `-Q` کوتیشن‌ها را از دست می‌دهد → از `LIKE` با فایل اسکریپت
  ASCII استفاده کنید.
- راه امن برای دادهٔ یونیکد و طولانی: فایل JSON بنویسید و از **خود API** استفاده کنید
  (`PUT /api/tasks/{id}/canvas`).

### گراف فرآیند دو شکل دارد (انفولپ و بدنهٔ خام) — مهم برای هر کدی که گراف را دست می‌زند

`Processes.GraphJson` یا **بدنهٔ خام** است (`{taskId,title,nodes,edges,dataSources,...}`) یا
**انفولپ**: `{title, graphJson:"<کل گراف به‌صورت رشتهٔ escape‌شده>", dataSources:[...]}`.

- در حالت انفولپ، `dataSources` **دو جا** هست: ریشهٔ انفولپ و داخل `graphJson` (منبع حقیقت).
- هر خواننده‌ای که اول `GraphJsonHelper.UnwrapEnvelope` نکند، `nodes` را پیدا نمی‌کند.
- هر **نویسنده‌ای** باید از `GraphJsonHelper.TryParseEnvelope` استفاده کند (هم شیء انفولپ،
  هم متن بدنهٔ داخلی).
- بازنویسی انفولپ با بدنهٔ خام از نظر محتوا سالم است ولی `LEN(GraphJson)` را کم می‌کند
  (تکرار رشتهٔ escape‌شده حذف می‌شود) — **نشانهٔ خرابی نیست**؛ گره‌به‌گره مقایسه کنید.

### الگوریتم سلکتور رکوردر فعلی (مبنای کار #3)

`extension-smart-recorder/content/selector.js` (~۲۶ خط):

```
cssPath(el):
  id دارد؟                → "#" + CSS.escape(id)                      [پایان]
  parts=[]; node=el
  تا عمق ۸:
    sel = tagName.toLowerCase()
    اگر node.id            → parts.unshift("#"+CSS.escape(id)); BREAK
    parent = node.parentElement
    اگر parent:
      same = parent.children با همان tagName
      اگر same.length > 1   → sel += ":nth-of-type("+(same.indexOf(node)+1)+")"
    parts.unshift(sel); node = parent
    اگر node.tagName==="BODY" → parts.unshift("body"); BREAK
  return parts.join(" > ")
```

ترجیح: `id` → tagName → `:nth-of-type(n)`، جداکننده `>`، عمق حداکثر ۸.
**کار #3 باید همین را به «کوتاه‌ترین سلکتور یونیک پایدار» ارتقا دهد:** attributeهای
جنریت‌شدهٔ ناپایدار (مثل `el_2551142555442xds`) باید **کنار گذاشته شوند** و توالی عناصر از ریشه
(سبک Full XPath) ترجیح داده شود، چون پایدارتر است. همین رفتار باید در **منوی کانتکست** افزونه
برای «گزینه‌هایی که باید یونیک باشند» هم اعمال شود.
